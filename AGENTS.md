# Agent Guide: Updating Pixel WireGuard Tunnels

## Scope and safety

- The Android host is `pixel7pro`. Its selectable tunnels are `p7p-blowfish`
  and `p7p-fishfinger`.
- Both tunnels must use the keypair generated by this repository in
  `keys/pixel7pro/`. Never generate replacement keys in the WireGuard Android
  app.
- `keys/` and `dist/` are gitignored but contain secrets. Never print, paste,
  commit, or include private keys, preshared keys, generated configurations, or
  import archives in task annotations or chat output.
- Never force-add anything under `keys/` or `dist/`. Before every commit, inspect
  `git status --short` and `git diff --cached --name-only`; abort if either the
  staged paths or staged content contains key material or generated configs.
- Never run `rake clean` while preserving existing keys: `clean!` removes the
  entire `keys/` directory as well as `dist/`.
- Do not delete the unrelated `buetowdotorg` phone tunnel.
- Deleting phone tunnels, rotating keys, or installing gateway configuration is
  destructive/shared-state work. Obtain explicit user approval first. A normal
  phone refresh reuses the current keys and does not require gateway changes.

## Connect the Pixel over ADB

On the phone:

1. Enable Developer options by tapping **Settings > About phone > Build number**
   seven times.
2. Enable **Settings > System > Developer options > USB debugging**.
3. Connect a data-capable USB cable, unlock the phone, and accept **Allow USB
   debugging from this computer**. Selecting **Always allow** avoids repeated
   prompts.

On the workstation:

```sh
adb start-server
adb devices -l
```

Continue only when the Pixel is listed with state `device`. An empty list means
USB debugging is not active; `unauthorized` means the phone approval dialog is
still pending. `lsusb` can distinguish a missing USB connection from an
ADB-authorization problem.

Confirm that the screen is unlocked before UI automation:

```sh
adb shell dumpsys window \
  | rg 'mDreamingLockscreen|mShowingLockscreen|mCurrentFocus'
```

ADB cannot bypass the PIN. Ask the user to unlock the phone and leave its screen
on if the keyguard is showing.

## Generate the two phone configurations

Generate from the repository root:

```sh
bundle exec rake generate
```

Expected files:

```text
dist/pixel7pro/etc/wireguard/p7p-blowfish.conf
dist/pixel7pro/etc/wireguard/p7p-fishfinger.conf
```

Each file must contain one peer, the corresponding gateway endpoint, and
`AllowedIPs = 0.0.0.0/0, ::/0`. Verify that both use the repository-generated
Pixel key without printing key material:

```sh
repo_pub=$(tr -d '\n' < keys/pixel7pro/pub.key)
for conf in dist/pixel7pro/etc/wireguard/p7p-{blowfish,fishfinger}.conf; do
  test "$(sed -n 's/^PrivateKey = //p' "$conf" | wg pubkey)" = "$repo_pub"
  test "$(rg -c '^\[Peer\]$' "$conf")" -eq 1
  rg -q '^AllowedIPs = 0\.0\.0\.0/0, ::/0$' "$conf"
done
```

Do not display either configuration while checking it.

## Import refreshed configurations

WireGuard Android does not expose a supported ADB command for importing tunnel
configurations. Use ADB to stage an archive and then import it through the app's
file picker:

```sh
rm -f /tmp/pixel7pro-wireguard.zip
zip -j /tmp/pixel7pro-wireguard.zip \
  dist/pixel7pro/etc/wireguard/p7p-blowfish.conf \
  dist/pixel7pro/etc/wireguard/p7p-fishfinger.conf
adb push /tmp/pixel7pro-wireguard.zip \
  /sdcard/Download/pixel7pro-wireguard.zip
adb shell am start -n \
  com.wireguard.android/.activity.MainActivity
```

In WireGuard, use **Add tunnel > Import from file or archive**, open Downloads,
and choose `pixel7pro-wireguard.zip`. Tunnel names are limited to 15 characters.

If tunnels with the same names already exist, delete only `p7p-blowfish` and
`p7p-fishfinger` before importing their replacements. Inspect the live UI first:

```sh
adb shell uiautomator dump /sdcard/wireguard-window.xml
adb pull /sdcard/wireguard-window.xml /tmp/wireguard-window.xml
sed 's/></>\n</g' /tmp/wireguard-window.xml \
  | rg 'resource-id="com.wireguard.android:id/tunnel_name"'
```

For ADB UI input, derive tap coordinates from the current XML bounds; never
reuse hard-coded coordinates. Long-press the first intended row, select only the
other intended rows, and confirm the action bar reports the expected selection
count before tapping the Delete button. Keep `buetowdotorg` untouched.

After a successful import, remove both copies of the secret archive and any UI
dumps:

```sh
adb shell rm -f /sdcard/Download/pixel7pro-wireguard.zip \
  /sdcard/wireguard-window.xml
rm -f /tmp/pixel7pro-wireguard.zip /tmp/wireguard-window.xml
```

## Verify both tunnels independently

Use the WireGuard UI to enable only one tunnel at a time. For each of
`p7p-blowfish` and `p7p-fishfinger`, verify:

1. Android reports the expected session as `VPN CONNECTED` and `IS_VALIDATED`.
2. `tun0` has `192.168.2.201/32` and `fd42:beef:cafe:2::201/64`.
3. Both IPv4 and IPv6 default routes use `tun0`.
4. Phone traffic succeeds.
5. The selected gateway receives a fresh Pixel handshake and increasing transfer
   counters; the other gateway does not receive a fresh handshake from this test.

Useful phone-side commands:

```sh
adb shell dumpsys connectivity \
  | rg 'VPN CONNECTED|sessionId=p7p-|InterfaceName: tun0|0\.0\.0\.0/0|::/0'
adb shell ping -c 3 -W 3 1.1.1.1
```

Gateway-side checks use the OpenBSD gateways' SSH configuration from
`wireguardmeshgenerator.yaml` (currently user `rex`, port `2`) and `doas wg show
wg0`. Compare handshake timestamps and transfer counters before and after each
phone test. Public keys may be compared, but do not print PSKs or private keys.

Leave `p7p-fishfinger` active after successful verification unless the user asks
for a different final state.

## Actual Pixel key rotation

Most updates are imports of regenerated configs using the existing keypair. If
the user explicitly requests a cryptographic key rotation:

1. Back up the existing `keys/pixel7pro/` securely; never put the backup in git
   or shared phone storage.
2. Replace/regenerate the Pixel private/public keypair through `KeyTool` rather
   than in Android. Key generation happens only when either key file is absent.
3. Regenerate `pixel7pro`, `blowfish`, and `fishfinger` configurations.
4. With explicit approval, install/reload the updated gateway configs before
   importing the new phone tunnels. Rotating the Pixel public key without
   updating both gateways makes both phone tunnels fail authentication.
5. Import and independently verify both phone tunnels using the procedure above.
6. Remove all temporary archives and securely remove the old key backup only
   after both gateways have been verified.

Do not claim a rotation or successful tunnel update from generated-file checks
alone. Completion requires fresh authenticated handshakes and phone traffic
through both gateways.
